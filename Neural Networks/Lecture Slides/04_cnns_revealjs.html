The parameter problem

# A modest image: 1000x1000 pixels, RGB colour
1000 * 1000 * 3            # = 3,000,000 inputs

# A hidden layer with 1,000 neurons
1000 * 1000 * 3 * 1000     # = 3,000,000,000 weights

3 billion parameters — for the first layer alone.

Warning

This is not primarily a storage problem. It is a generalisation problem: a fully-connected layer cannot share what it learns about a galaxy at one position with the same galaxy at another position.

What fully-connected layers miss

A spiral galaxy at pixel (100, 100) and the same galaxy at pixel (800, 800):

  • identical in morphology
  • completely different inputs to nn.Linear

Every position requires its own weights. No knowledge transfers across the image.

class GalaxyMLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(
            256 * 256 * 3,    # 196,608 inputs
            512,
        )
        # 196,608 x 512
        #   = 100,663,296 weights
        #   ... just for layer 1

Translation invariance

A useful detector for galaxy spiral arms should fire whether the arm appears:

  • at the top of the image
  • at the bottom
  • anywhere else

Note

The key idea: apply the same small filter everywhere.
If a filter detects an edge, it detects that edge regardless of position. The filter learns the pattern; the image tells it where.

Translation invariance and weight sharing are the two properties that convolutional layers encode by construction.

Convolution by hand — 1D

A 1D signal and a 3-element edge-detecting filter:

\[ \text{filter} = [1,\ 0,\ -1] \]

At each position, compute the dot product of filter with the signal window beneath it.

Output length: \(L_{out} = L_{in} - k + 1\)

nn.Conv1d does this simultaneously at every position — filter weights are learned from data.

Convolution by hand — 1D

2D convolution

A \(k \times k\) filter slides over a 2D image.

Output size (no padding, stride 1):

\[ H_{out} = H_{in} - k + 1 \qquad W_{out} = W_{in} - k + 1 \]

General formula (padding \(p\), stride \(s\)):

\[ H_{out} = \left\lfloor \frac{H_{in} + 2p - k}{s} \right\rfloor + 1 \]

Setting \(p = \lfloor k/2 \rfloor\) gives \(H_{out} = H_{in}\) (“same” padding).

nn.Conv2d(
    in_channels=3,       # RGB
    out_channels=32,     # 32 filters
    kernel_size=3,       # 3x3
    padding=1,           # same size out
)
# Parameters:
#   3 x 3 x 3 x 32 + 32 = 896

One filter learns one feature. 32 filters learn 32 different features — all from the same spatial positions.

2D convolution

Parameter sharing

Fully-connected, first layer:

\(256 \times 256 \times 3\) inputs, 512 outputs \(\to\) 100 M weights

Each neuron looks at the whole image.

Convolutional, first layer:

\(3{\times}3\) filter, 3 ch in, 32 out \(\to\) 896 weights

The same 896 weights scan every position.

A CNN encodes the prior: the pattern matters, not its position.

Pooling

After convolution, reduce spatial resolution deliberately:

nn.MaxPool2d(kernel_size=2, stride=2)
# 256x256 -> 128x128  (halves each spatial dimension)

What pooling does:

  • Discards exact position information
  • Retains whether a feature was detected in that region
  • Reduces computation for all subsequent layers

Spatial dimensions after 3x MaxPool2d(2,2) on a 256x256 image:

\[ 256 \ \to\ 128 \ \to\ 64 \ \to\ 32 \]

The classifier head then sees a \(32 \times 32\) feature map — 64x smaller than the input.

What filters learn — hierarchical features

Layer What filters detect Astronomy analogy
Layer 1 Edges, colour gradients Limb of a galaxy disc, star PSF
Layer 2 Textures, curved strokes Spiral arm segments, bar
Layer 3 Object parts Bulge, ring, extended emission
Layer 4 Whole objects Morphological class

Note

Zeiler & Fergus (2013) visualised this by projecting learned filter weights back into pixel space. The hierarchy emerges from the data — it is not hand-designed.

GalaxyCNN: a concrete architecture

class GalaxyCNN(nn.Module):
    def __init__(self, n_classes=10):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3,   32, 3, padding=1), nn.BatchNorm2d(32),  nn.ReLU(),
            nn.MaxPool2d(2),                                        # 256 -> 128
            nn.Conv2d(32,  64, 3, padding=1), nn.BatchNorm2d(64),  nn.ReLU(),
            nn.MaxPool2d(2),                                        # 128 -> 64
            nn.Conv2d(64, 128, 3, padding=1), nn.BatchNorm2d(128), nn.ReLU(),
            nn.MaxPool2d(2),                                        # 64  -> 32
        )
        self.classifier = nn.Sequential(
            nn.Dropout(0.5),
            nn.Linear(128 * 32 * 32, 256), nn.ReLU(),  # 131,072 -> 256
            nn.Linear(256, n_classes),
        )

Total parameters: ~34 M (dominated by the first classifier layer, Linear(128*32*32, 256) ≈ 33.5 M) — versus ~100 M for the first layer alone of an equivalent fully-connected network.

In practice: which architecture when?

Note

Start simple. Add complexity only when you have evidence you need it.

Problem First choice When to go further
Tabular / catalogue data MLP Rarely needed
Fixed-size images, position-invariant CNN GPU available, dataset > ~5k
Long-range dependencies in images CNN + attention Large dataset, competitive task
Sequence (spectra, time series) 1D CNN or Transformer > ~10k labelled examples
Small labelled dataset Pre-trained CNN (fine-tune) Almost always

Warning

A ViT trained from scratch needs ~1M+ images to beat a CNN. With 5,000 labelled galaxies, a well-tuned CNN is almost always better.

Astronomy-specific gotchas

Rotational invariance. Galaxies appear at any position angle. CNNs are translationally invariant but not rotationally invariant.

  • Data augmentation: random rotation during training
  • Equivariant architectures (E(2)-CNNs)
  • Or simply train on enough orientations

Class imbalance. Spirals outnumber ring galaxies ~20:1 in most surveys.

  • Weighted cross-entropy loss
  • Oversample rare classes
  • Report per-class F1, not just accuracy

Warning

A classifier that always predicts “spiral” scores ~70% accuracy on GalaxyZoo. Accuracy alone is a misleading metric here.

Case study: pulsar candidate classification

Luna et al. (2021) — classifying pulsar candidates from the HTRU survey.

Input: a 4-panel diagnostic plot per candidate (folded profile, sub-band profile, sub-integration profile, DM–time plot). Model: a CNN on each panel, outputs merged.

Result: 99.2% recall / 95% precision — versus ~87% recall for manual inspection.

Lessons that generalise:

  • Human-interpretable features (pulse width, DM) guided the CNN input design
  • Class imbalance was severe (~1 pulsar per 1000 candidates): weighted loss and oversampling both needed
  • The model transfers to new observations only if trained on similar telescope systems
