The bug everyone hits first

You will write your first network. It will fail with something like:

RuntimeError: mat1 and mat2 shapes cannot be multiplied (5x2 and 8x1)

This is not a deep-learning error. It is a shape error.

The claim of this lecture: almost everything you do — a neuron, a layer, a whole U-Net, even the gradient — is a rule for turning one shaped box of numbers into another. Learn to read shapes and you can read any architecture.

PyTorch in 60 seconds

PyTorch is “NumPy that runs on a GPU and remembers how to differentiate itself.” If you know NumPy arrays, you know most of torch.Tensor.

a = torch.tensor([1., 2., 3.])   # create
r = torch.randn(2, 3)            # random, shape (2,3)
r.shape, r.dtype, r.device      # inspect: the 3 questions to always ask
a + 10,  a * a,  a.mean()        # operate: elementwise + reductions
M[0],  M[:, 1]                   # index / slice, just like NumPy
a.numpy(),  a.item(),  a.to(device)   # convert / move to GPU

Everything in this lecture — data, weights, images, gradients — is a torch.Tensor. The one habit worth building: print .shape constantly.

The linear algebra you need

Neural networks use a small slice of linear algebra. Three operations carry almost everything:

Operation Shapes What it is
dot \(\mathbf{w}\cdot\mathbf{x}\) \((n)\cdot(n)\to\) scalar one neuron
matrix × vector \(W\mathbf{x}\) \((H,n)\times(n)\to(H)\) one input, \(H\) neurons
matrix × matrix \(XW\) \((N,n)\times(n,H)\to(N,H)\) a batch, \(H\) neurons

Plus transpose (swap axes so inner dims line up) and reductions (sum, mean, norm — the loss is a reduction to one number).

The dot product is a one-neuron layer. The matrix multiply is that same idea for every neuron and every example at once.

A neural network in one picture

Five words: multiply, add, bend, repeat, score.

\[\mathbf{x} \xrightarrow[W_1,\mathbf{b}_1]{\text{mult+add}} \mathbf{z}_1 \xrightarrow[\sigma]{\text{bend}} \mathbf{a}_1 \xrightarrow[W_2,\mathbf{b}_2]{\text{mult+add}} \hat{\mathbf{y}} \xrightarrow[\text{loss}]{\text{score}} L\]

  • multiply + add — X @ W + b, a linear map (rotate, scale, shift)
  • bend — a non-linear \(\sigma\); without it, stacked layers collapse to one linear map
  • repeat — chain blocks; “deep” just means many
  • score — the loss collapses prediction + truth to one scalar \(L\) to minimise

Everything that follows is this picture, traced by its shapes.

Scalars, vectors, tensors

A tensor is a box of numbers with a fixed number of axes.

  • rank = number of axes
  • shape = length along each axis
Rank Name Astronomy example Shape
0 scalar one flux measurement ()
1 vector a galaxy’s colours \((g\!-\!r,\ r\!-\!i)\) (2,)
2 matrix a batch of galaxies, or a grayscale image (N, 2) / (H, W)
3 3-tensor a batch of images, or a multi-band image (N, H, W) / (C, H, W)
4 4-tensor a batch of multi-band images (N, C, H, W)

A vector is a list of numbers. A matrix is a grid. A tensor is the same idea with as many axes as you need. Nothing more mysterious than that.

The batch dimension

The first axis is almost always the batch: independent examples stacked together.

one_galaxy  = torch.tensor([0.35, 0.12])   # shape (2,)     one example
many_galaxy = torch.randn(200, 2)          # shape (200, 2) a batch of 200

A network processes all N examples at once. The maths for one example is repeated in parallel across the batch — the shape carries the loop for you.

Note

This is why you almost never write for galaxy in dataset:. You feed the whole (N, 2) block through and let the matrix multiply do all N at once. This is also why GPUs matter — they do that parallel work.

Same numbers, different shapes

A galaxy is a vector.

\[\mathbf{x} = (g\!-\!r,\ r\!-\!i) \in \mathbb{R}^2\]

Two features, shape (2,).

A batch of 200 galaxies is a matrix, shape (200, 2).

An image is a matrix.

A \(32\times32\) sky patch is shape (32, 32).

A convolutional network wants it as (N, C, H, W) — batch, channels, height, width — even for one grayscale image:

img.unsqueeze(0).unsqueeze(0)
# (32,32) -> (1, 1, 32, 32)

The data never changes — only how we arrange it into axes. Notebook Part 0 builds each of these and prints its shape.

Reshaping: same numbers, new axes

A tensor’s numbers are one flat run in memory; the shape is just a lens on it. Rearranging axes is (almost) free:

  • reshape / flatten — regroup the same elements, same order. -1 = “infer this axis”.
  • transpose / .T — swap axes; this genuinely reorders the data.
  • unsqueeze / squeeze — add / remove a length-1 axis.
imgs = torch.randn(4, 1, 32, 32)   # (N, C, H, W)
imgs.reshape(4, -1)                # (4, 1024)  flatten for a dense layer

The transpose hides inside nn.Linear, which stores its weight as (out, in) and computes X @ W.T. Notebook: interactive reshape cell.

Broadcasting — and the silent bug

Tensors of different shapes can still be combined. Broadcasting rule:

Line the shapes up from the right. Any axis that is length-1 (or missing) is stretched to match — without copying data.

This is why Z + b works: a bias (H,) stretches across all N rows of (N, H).

Warning

It is also the #1 silent bug. A (N,1) prediction minus a (N,) target does not error — it broadcasts to (N, N) and quietly corrupts the loss.

y_hat.shape, y.shape        # (100, 1), (100,)
(y_hat - y).shape           # (100, 100)  <-- NOT (100,) !

The notebook has a widget to combine shapes and spot the trap.

One neuron = one dot product

From Lecture 01, a single neuron takes a weight vector and an input vector and returns one number:

\[z = \mathbf{w}\cdot\mathbf{x} + b = \sum_i w_i x_i + b \qquad (2,)\cdot(2,) \to \text{scalar}\]

w = torch.randn(2)        # weight VECTOR, shape (2,)
x = torch.randn(2)        # one galaxy,    shape (2,)
z = x @ w + b             # a single number

The dot product is the smallest possible “shape collapse”: two length-2 vectors go in, one scalar comes out. Every layer is built from this.

A layer = a matrix multiply

Want \(H\) neurons instead of one? Give each its own weight vector and stack them as columns of a matrix \(W \in \mathbb{R}^{2 \times H}\).

Process a whole batch \(X \in \mathbb{R}^{N\times 2}\) at once:

\[Z = X\,W + \mathbf{b}, \qquad \underbrace{(N,2)}_{X}\ \times\ \underbrace{(2,H)}_{W}\ \to\ \underbrace{(N,H)}_{Z}\]

X = torch.randn(200, 2)      # batch of galaxies
W = torch.randn(2, 8)        # 8 neurons, each a weight vector
Z = X @ W + b                # (200,2) @ (2,8) -> (200,8)

A weight vector became a weight matrix. That is the entire jump from a neuron to a layer. Notebook Part 1.

Matrix multiply, one cell at a time

Each output cell is one row of \(X\) · one column of \(W\). The shared inner 2 is consumed; the outer N and H survive.

The one rule for matrix multiply

\[\underbrace{(N,\ \mathbf{2})}_{X}\ \times\ \underbrace{(\mathbf{2},\ H)}_{W}\ \to\ (N,\ H)\]

Inner dimensions must match and cancel. Outer dimensions survive.

  • The 2 (input features) is consumed — it must agree on both sides.
  • N (batch) and H (neurons out) survive into the result.

That failed error message from earlier — (5x2 and 8x1) — is just the inner dims 2 and 8 refusing to cancel.

Tip

Debugging networks is 90% checking that (batch, in) @ (in, out) lines up at every layer. Print .shape. Always.

Two layers, different shapes, one loss

Stack two layers with deliberately different weight shapes:

\[\underbrace{X}_{(N,2)} \xrightarrow{\;W_1\,(2,8)\;} \underbrace{H_1}_{(N,8)} \xrightarrow{\text{ReLU}} \underbrace{A_1}_{(N,8)} \xrightarrow{\;W_2\,(8,1)\;} \underbrace{\hat{y}}_{(N,1)} \xrightarrow{\text{MSE}} \underbrace{L}_{()}\]

\(W_1\) is (2,8), \(W_2\) is (8,1) — totally different. They chain because the 8 out of layer 1 is exactly the 8 into layer 2. That single agreement is all that makes a network well-formed.

However wide or deep, everything funnels to a single scalar loss () — the one number we minimise. Notebook Part 2.

What is a gradient?

For one number in, one number out, the gradient is just the slope — how much \(L\) changes if you nudge the input.

With many parameters, the gradient is the vector of all the partial slopes:

\[\nabla_{\mathbf{w}} L = \left(\frac{\partial L}{\partial w_1},\ \frac{\partial L}{\partial w_2},\ \dots\right)\]

  • Each entry: “if I increase this one weight, does the loss go up or down?”
  • The gradient points uphill — toward larger loss.
  • So to reduce loss, step in the opposite direction.

A gradient is not exotic. It is one slope per parameter, packed into a tensor.

Gradient descent

\[\mathbf{w} \leftarrow \mathbf{w} - \eta\,\nabla_{\mathbf{w}} L\]

Step downhill by a small amount \(\eta\) (the learning rate), repeat. This is the entire learning algorithm — the notebook’s training loop is just this line run thousands of times.

Feature scaling — what shapes can’t show

Shapes tell you the maths is legal. They say nothing about whether it converges. The most common reason a correctly-shaped network won’t learn is unscaled inputs.

One shared step size \(\eta\) must serve every weight. But a feature’s gradient scales with its magnitude. If one column is ~500× larger than another, their gradients differ by orders of magnitude — no single \(\eta\) works. The loss surface becomes a long thin valley: the optimiser crawls, or diverges.

Fix — standardise each feature:

\[x' = \frac{x - \mu}{\sigma}\]

so every input column has mean \(\approx 0\), std \(\approx 1\).

Same data, same shape — dramatically better conditioning. Use the training \(\mu,\sigma\) on val/test too.

The notebook has a widget: slide feature-scale × learning-rate and watch raw diverge while standardised converges.

Gradients have the same shape as their parameters

This is the fact that ties gradients back to shapes:

\[\text{shape}\big(\nabla_{W} L\big) = \text{shape}(W)\]

W1 = torch.randn(2, 8, requires_grad=True)   # weight  (2, 8)
W2 = torch.randn(8, 1, requires_grad=True)   # weight  (8, 1)
loss.backward()
W1.grad.shape        # (2, 8)  <- same as W1
W2.grad.shape        # (8, 1)  <- same as W2

Of course it must: there is exactly one slope per weight, so the bag of slopes has exactly the same shape as the bag of weights. The update \(W \leftarrow W - \eta\,\nabla_W L\) then subtracts two identically-shaped tensors. Notebook Part 2.

loss.backward() in one line

You will not compute those partials by hand. PyTorch records every operation and applies the chain rule backward through them:

y_hat = torch.relu(X @ W1 + b1) @ W2 + b2   # forward: shapes flow FORWARD
loss  = torch.mean((y_hat - y) ** 2)        # collapse to a scalar ()
loss.backward()                             # gradients flow BACKWARD
  • Forward: shapes go (N,2) → (N,8) → (N,1) → ().
  • Backward: gradients retrace the same path, each with its parameter’s shape.

Note

Lecture 03 opens up backward() and derives the chain rule. For today: it fills every .grad with a same-shaped gradient. That is all you need.

Shape is architecture — U-Net

So far shapes only got narrower: 2 → 8 → 1. For images, architectures also reshape space. The U-Net is the clearest example — its name is a picture of the spatial size:

  input  (1, 32, 32)
     | encoder: conv, then downsample  (halve H,W; grow channels)
   (16, 16, 16)
   (32,  8,  8)   <- bottleneck: smallest space, most channels
     | decoder: upsample  (double H,W; shrink channels)
   (32, 16, 16) --concat-- skip from encoder (32, 16, 16)
   (16, 32, 32) --concat-- skip from encoder (16, 32, 32)
  output (1, 32, 32)

The “U” is a plot of (H, W): down the left arm, bottom, up the right arm.

Reading the U-Net by its shapes

The notebook’s MiniUNet prints its own shape trace:

input        (4,  1, 32, 32)
enc1         (4, 16, 32, 32)
enc2         (4, 32, 16, 16)
bottleneck   (4, 64,  8,  8)
up2          (4, 32, 16, 16)
cat+dec2     (4, 32, 16, 16)
up1          (4, 16, 32, 32)
cat+dec1     (4, 16, 32, 32)
output       (4,  1, 32, 32)

Two things to notice:

  1. Spatial size \(32 \to 16 \to 8 \to 16 \to 32\). That path is literally the letter U.

  2. The skip connections torch.cat([up, enc]) only work because the encoder feature and the decoder feature have the same shape at each level (16×16 meets 16×16).

An architecture is a set of shape-matching constraints. Nothing more.

Same training, bigger tensors

The U-Net has 56,689 parameters and works on (N,1,32,32) images instead of (N,2) vectors. But nothing about learning changed:

  • forward pass produces a prediction,
  • MSE collapses it to a single scalar loss (),
  • loss.backward() fills each parameter’s .grad (same shape as the parameter),
  • gradient descent steps downhill.

A (2,8) weight matrix and a (32,16,16) feature map are trained by the exact same four steps. Scale is just bigger boxes of numbers.
